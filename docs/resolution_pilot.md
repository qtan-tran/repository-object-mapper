# Resolution pilot

> This document is a **template**. The live version is automatically
> regenerated by `rom resolve-pilot`, which samples 500 identifiers from
> the Zenodo harvest, runs the resolution pipeline against them, and
> writes the result here. The template below describes what that
> regenerated document contains and how to read it.

## Purpose

Identifier resolution is the highest-impact technical risk in this work.
If the fully-typed rate is materially below expectation (the review
notes that 70% is optimistic), object embeddedness claims must be
conditioned on resolution tier. The pilot runs **first, before the full
pipeline**, so that scoring and analysis are designed with realistic
resolution rates in view.

## What the live document contains

The auto-generated version replaces this template on each `rom
resolve-pilot` run with:

- **Mode.** `mock` or `live`.
- **Sample size.** Number of identifiers actually sampled (≤ 500 at
  v0.2).
- **Per-tier breakdown.** A table of counts and rates for `fully_typed`,
  `weakly_typed`, and `unresolved`.
- **URL-only share of unresolved.** The proportion of unresolved
  identifiers that are URLs rather than persistent identifiers — a
  separate diagnostic of how much of the unresolved pool is
  intrinsically unresolvable (URL-only) versus resolvable-in-principle
  (DOI that failed lookup, unknown scheme).
- **Interpretation notes.** A short statement of what the observed rates
  imply for object embeddedness reporting.

## How to read the results

The pilot's primary diagnostic is the **fully-typed rate**. Indicative
thresholds:

- **≥ 70%.** Object embeddedness can be reported with `fully-only` as
  the primary inclusion policy with reasonable confidence.
- **50–70%.** Report both `fully-only` (primary) and `fully+weakly`
  (sensitivity); discuss the gap explicitly in the paper.
- **< 50%.** Object embeddedness becomes a second-order finding.
  Relational and agent dimensions carry the H2 argument; object
  embeddedness is reported with explicit caveats, and the pilot result
  is cited in methods as a scope restriction.

The **URL-only share of unresolved** separates two kinds of resolution
failure: repositories that deposit their relations primarily as
persistent identifiers versus as URLs. This interacts with the
cross-repository comparison — a repository whose relations are
overwhelmingly URL-only cannot be compared on object embeddedness on
the same footing as a repository whose relations are overwhelmingly
DOI-based.

## Reproducing the pilot

```bash
rom harvest --config config/sample_v0_2.yaml --mock   # or --live
rom classify
rom resolve-pilot --mock -n 500                       # or --live
```

The resulting summary is also emitted as stdout JSON for scripting.
